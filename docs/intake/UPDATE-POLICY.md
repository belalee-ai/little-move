## 每轮做什么

1. **盘点**：读取当前源码目录和候选报告，计算下一固定编号。已有编号不改，不用旧文档中的历史数量代替当前目录。
2. **发现**：查找原作者、官方文档、原创仓库和真实 Demo，记录来源、作者、检索日期、许可与动作机制。聚合页只做线索。
3. **比较**：与现有全部词条对比，确认新的触发方式、空间关系、状态变化或运动路径。语义去重需要真实观看，脚本的特征字符串不能代替判断。
4. **制作**：保持可替换素材、可调参数和简短提示词；按钮就是按钮、输入就是输入。自动演示与视频采用同一套帧驱动逻辑。
5. **逐项验收**：真实播放完整运动，检查动作是否明确、节奏是否自然、文字是否可读、首尾是否连续、比例与遮挡是否正确；交互检查中途反向、松手、键盘和减少动态效果。查对应真实渲染帧。失败项不计入正式收录。
6. **发布与回读**：相关检查和构建通过后，只提交本轮必需文件，更新目录、提示词、来源、项目头图和受影响截图。推送后等待 GitHub Pages 发布，再打开线上新增或修改的词条验证。推送成功和实际上线分开记录。

当前流程由 AI 助手结合浏览器与本地工具执行，不是一个只运行候选统计脚本就能自动生成动效的程序。环境不可用或验收做不完时，保留候选与明确的未完成状态。

## 质量门槛

- 新机制能从画面中辨认，不能靠名称或说明“解释出”实际看不到的效果。
- 同类效果并排比较；高相似度内容归入原词条变体，避免重复编号。
- 字体不因过粗、过暗、描边、光晕而糊成一团；装饰不能妨碍理解。
- 使用来源明确的素材；上游代码、字体、摄影、音频分别核验，不把“看过参考”当成获得素材授权。
- 代码检查、浏览器预览和渲染检查各自保留结果，不能以构建成功代替视觉验收。
- 原有稳定动效不被无关改动扰动；已有私人文件和无关改动不进入公开提交。

## 手动提前运行

可以对有项目文件和浏览器权限的 AI 助手说：

> 按 Little Move 的 docs/intake/WORKFLOW.md 和 UPDATE-POLICY.md 提前运行一轮补充。
> 不限数量，先对比全部现有动作，再制作和逐项验收。
> 检查通过后按当前授权发布到 GitHub 和在线网站，并回读上线结果。

先运行盘点命令：

```bash
node scripts/catalog-intake.mjs
# 只校验，不写 report.json
node scripts/catalog-intake.mjs --check
```

候选数据放在 `candidates.json`；运行策略放在 `policy.json`；`report.json` 是盘点快照。它们都不能替代浏览器检查、素材许可核验或正式收录。

## 运行结果与失败处理

有可验收成果时报告：新增编号与名称、优化的旧编号、验证证据、GitHub 提交、线上结果、待确认项。候选数、实现数、验收数分别统计。没有变化且没有需要处理的阻塞时不打扰。

来源或许可不清楚的先留候选；构建、渲染或上线回读失败时停止发布流程并报告原因。保留可恢复的正常版本，不强推、不删除现有证据、不通过关闭检查掩盖失败。后续运行从未完成项继续，不把上轮失败算成已发布。
